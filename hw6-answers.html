(ii) With two threads each incrementing four times, largest = 8 and smallest = 2.
One schedule producing 2:
T1 load0; T1 add→1; T0 load0; T1 store1; T1 load1; T1 add→2; T1 store2; T1 load2; T1 add→3; T1 store3; T0 add→1; T1 load1; T1 add→2; T0 store1; T0 load1; T0 add→2; T0 store2; T0 load2; T0 add→3; T0 store3; T0 load3; T0 add→4; T0 store4; T1 store2.
No result below 2 is possible because every store from an increment writes at least 1, and the thread making the final store is completing its fourth increment; its fourth load cannot be below 1, so after adding one its final store is at least 2.

1(c)

On one CPU, disabling interrupts prevents preemption, so no other thread can execute the protected run-queue code until interrupts are enabled again. Costs include higher interrupt latency and poor responsiveness/time sharing; a long or buggy critical section can stall the machine. On four cores, disabling interrupts is local to a core: one thread can enter on core 0 while another thread independently enters on core 1, so mutual exclusion is lost.

1(d)

If bolt=0, CAS returns 0 and atomically writes 1. If bolt=1, it returns 1 and leaves bolt unchanged. Atomic read+write prevents the read-then-set race in scheme F. After P1 releases, any spinner—or P1 again—may win; P4 can starve, so requirement 3 is at risk. On one CPU with strict priorities, high-priority H spins while low-priority L holds the lock; H prevents L from running to release it, so H can spin forever.

2(b)

Full buffer start s=1,n=2,e=0. P wait(s)→s=0. P wait(e)→e=-1 and P blocks while holding s. C wait(n)→n=1. C wait(s)→s=-1 and C blocks. P waits for C to consume and signal e; C waits for P to release s: deadlock. The same can happen later when a not-full buffer becomes full and P starts another iteration, locks s, then waits on e=0. Swapping the two signal operations does not create the same deadlock because signals do not block.

W1 waits 11 units with readers priority and 3 units with writers priority. If a new reader arrives every 3 units forever under readers priority, readers overlap continuously and W1 may never run; this is writer starvation.

2(d)

The one mailbox message is a token giving permission to enter. A process must receive it before entering and sends it back after leaving, so one token means at most one process inside. Two starting messages permit two simultaneous entrants; zero starting messages deadlock everyone. If receive returned empty-handed instead of blocking, processes could enter without the token and mutual exclusion would fail.

Contiguous needs one long run of free blocks, so external fragmentation occurs. Chained and indexed can use scattered blocks. If the pointer in chained block 12 is damaged, blocks 13–49 (37 blocks) become unreachable through the chain.

4(c)

4 TiB/4 KiB=2^28=268,435,456 blocks. Bitmap size=268,435,456 bits=33,554,432 bytes=32 MiB=about 0.00305% of disk, occupying 8,192 disk blocks. A block number needs 28 bits, stored in 4 bytes; an explicit list of every free block on an empty disk would be 2^28×4=1,073,741,824 bytes=1 GiB. Repeatedly scanning the bitmap from the start becomes slow as early blocks fill; a summary/hierarchical free-space table lets the OS jump to a bitmap region known to contain free blocks.

B-b

Look-then-flag fails mutual exclusion because both can observe false before either raises its flag (requirement 1). Flag-then-look can deadlock when both raise flags and then each waits for the other (requirement 3). Strict turns fails because T0 finishes after one visit while T1 still needs another; turn returns to T0 and T1 waits forever, so a process stopped outside the CS prevents progress (requirement 2).
Peterson works because when both flags are true, the single turn variable breaks the tie: they cannot both satisfy the waiting condition in the way needed to enter together, and at least one has a path forward. The checker proves a completion path exists from every state, not fairness. An unfair scheduler could leave T0 in its CS while repeatedly scheduling only T1's spin step; T1 would never enter. Under a fair scheduler T0 eventually exits and executes flag0=False, which releases T1.

B-c

With producer order changed to semWait(s) then semWait(e): Experiment 3 has 124 reachable states, mutual exclusion still says never, overflow/underflow never, but 2 states are stuck. In the shortest deadlock the producer fills the buffer to 2 items, starts another iteration, acquires s, and blocks on e=0. The consumer successfully waits on n but then blocks on s. Producer holds s and waits for consumer to make e positive; consumer waits for producer to release s. The mutual-exclusion check still passes because deadlock is a liveness failure, not two threads being inside simultaneously. Restoring semWait(e) before semWait(s) returns Experiment 3 to 125 states and 'can always still finish: yes'.
